**CONTROL REDESIGN 2026-08-19 — JOINT SPACE, WRIST FROZEN CAMERA-UP.** Cartesian `EndPoseCtrl` is now DEPRECATED for this robot; use `joint_planner.JointPlanner` + `piper_safe`. Reasons, all measured: (a) firmware IK *silently refuses* many targets (whole +Y half with a fixed orientation; short-radius+low-height) — the arm just doesn't move and reports `REACH_TARGET_POS_FAILED`; (b) IK picks its own wrist roll, which flips the **wrist-mounted D405 underneath the gripper** — risks camera + flange on every descent (USER CAUGHT THIS; jaws are symmetric so the flip is invisible by eye); (c) re-solving orientation swings **J6, the smallest motor** (carries gripper+camera): 66-77°C and repeated `motor_overheating` trips under Cartesian vs steady **37-38°C with the wrist frozen**; (d) with the taught (flipped) orientation there is a hard floor at **z=140mm** — the can can never be reached.

**GRIPPER CONTROL OVER CAN — SOLVED 2026-08-19 (was broken in ALL prior runs).** Symptom: `GripperCtrl` accepted silently, gripper never moved; user believed the gripper only worked in teach mode. TWO bugs: (1) we used `gripper_code=0x02` as the "enable handshake" but **0x02 = DISABLE+clear_err** (codes: 0x00 disable, 0x01 enable, 0x02 disable+clear, 0x03 enable+clear); (2) far more important, **the gripper only actuates while the arm is in CAN-control mode AND the command is streamed** — if `ctrl_mode` is `STANDBY(0x0)` every GripperCtrl is ignored. Working recipe (verified `test_gripper2.py`, moves 46-50mm reliably):
```python
t0=time.time()
while time.time()-t0 < 2.5:                       # STREAM it
    p.MotionCtrl_2(0x01, 0x01, SPEED, 0x00)       # hold CAN-control mode every tick
    p.GripperCtrl(um, 1000, 0x01, 0)              # um in 0.001mm (70000 = 70mm open)
    time.sleep(1/15)
```
effort 1000 is ample (5000 = no better). In run_policy.py the gripper is now re-commanded EVERY control tick alongside EndPoseCtrl (`send_pose_and_grip`) rather than on transitions — the v1/v2 deploy logs printed "gripper -> CLOSE" that never physically happened, so all earlier grasp attempts were doomed regardless of policy quality. `set_grip()` helper added to corner_check.py / calibrate_overhead.py / go_start.py. Gripper feedback (`GetArmGripperMsgs().gripper_state.grippers_angle`, 0.001mm) IS live in teach mode too — always verify actuation by reading the angle back, never trust the command.
